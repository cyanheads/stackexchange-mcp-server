# 0.1.12 — 2026-09-09

## Added

- **`creationDate`/`lastActivityDate` on questions and answers, `creationDate`/`lastAccessDate` on user profiles** — ISO 8601 timestamps built from data Stack Exchange already returns, rendered in both `structuredContent` and `format()` output across `stackexchange_search_questions`, `stackexchange_get_tag_faq`, `stackexchange_get_thread`, and `stackexchange_get_user` ([#19](https://github.com/cyanheads/stackexchange-mcp-server/issues/19)).

## Fixed

- **`stackexchange_list_sites` no longer silently drops sites past the first 200.** `getSites` walks pages under a `MAX_SITE_PAGES` ceiling instead of stopping after two; a `truncated` flag surfaces as a caller notice when the ceiling is hit before Stack Exchange's `has_more` clears ([#15](https://github.com/cyanheads/stackexchange-mcp-server/issues/15)).
- **Declared `recovery` hints now reach the caller for errors thrown inside `StackExchangeService`.** Every service throw site spreads `ctx.recoveryFor(reason)`, so `data.recovery.hint` and the mirrored `Recovery:` line in `content[0].text` carry the calling tool's declared text ([#16](https://github.com/cyanheads/stackexchange-mcp-server/issues/16)).
- **`stackexchange_get_user` now returns `answerCount` and `questionCount`.** The profile call sends a pinned custom filter, since Stack Exchange's default `/users/{id}` fields omit both.
- **`fetchSe`'s `bad_parameter` mapping no longer misattributes the rejected field to a question ID.** Each caller supplies its own mapping instead of `fetchSe` guessing; `stackexchange_get_user` also bounds `userId` at 2,147,483,647 in the handler, so an out-of-range ID is rejected with a declared reason and recovery hint rather than a message naming a field the tool doesn't have ([#21](https://github.com/cyanheads/stackexchange-mcp-server/issues/21)).
- **A whitespace-only `filter` on `stackexchange_list_sites` no longer logs as a filtered call.**
