# 0.1.16 — 2026-10-08

## Changed

- **`@cyanheads/mcp-ts-core` 0.13.6 → 0.13.14**.
- **Argument repair** (mcp-ts-core 0.13.14): a numeric string sent for a number field (`pageSize: "3"`) is accepted as the number, and `null` at an optional key is treated as absent; a boolean sent for a number field is still rejected.
- **Tool error results** (mcp-ts-core 0.13.10) end with `request <id>` and carry `data.requestId`, matching the server's log records.
- **`server.json` npm entries** no longer pass `run start:*` arguments and set `runtimeHint: npx`; the streamable-http entry sets `MCP_TRANSPORT_TYPE` to `http`, so a registry client launching it starts the HTTP transport (scaffold change from mcp-ts-core 0.13.11).
- **Docker image** installs production dependencies in a `deps` stage on the build platform (mcp-ts-core 0.13.10), prunes musl-only packages (0.13.11), and uses Bun 1.4.2 base images (0.13.7).
- **Telemetry config**: with `OTEL_ENABLED=true`, `OTEL_EXPORTER_OTLP_ENDPOINT` alone now exports traces and metrics, and a deployment with no endpoint exports nothing (mcp-ts-core 0.13.7); `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` and `LOG_TOOL_FAILURE_PAYLOADS` are documented as opt-ins (0.13.8).
- **Declared recovery hints** are filled by the framework, so the tools no longer forward `ctx.recoveryFor`; nothing changes on the wire.
- **Ignore files**: `.gitignore` and `.dockerignore` cover every `.env*` file (`.env.example` stays tracked) and `.dockerignore` adds the MCP Registry token files; `.mcpbignore` excludes `docs/idea.md`, `logs/`, `.cache/`, `coverage/`, and `tests/` from the bundle.
- **`package.json`** excludes `dist/*.mcpb` from the npm tarball.
- **CodeQL workflow** analyzes `actions` and `javascript-typescript` as separate matrix jobs, each under its own `/language:<language>` category.
- **`framework-skills/`, `CLAUDE.md`/`AGENTS.md`, and the build and lint scripts** are re-synced to the 0.13.14 templates; `scripts/install-otel.ts` and `scripts/prune-musl-packages.ts` are new.
