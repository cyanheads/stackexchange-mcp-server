# 0.1.13 — 2026-09-09

## Added

- **`page` input on `stackexchange_search_questions` and `stackexchange_get_tag_faq`** — results past the `pageSize` cap are reachable, the tools echo the effective page, and paging past the keyless page-25 ceiling reports a declared `paging_depth_limit` reason ([#18](https://github.com/cyanheads/stackexchange-mcp-server/issues/18)).
- **`includeComments` on `stackexchange_get_thread`** — fetches the question's and every returned answer's comment thread in two additional upstream calls; a post absent from the fetched page reports its comments as unknown, never as none ([#20](https://github.com/cyanheads/stackexchange-mcp-server/issues/20)).

## Fixed

- **`stackexchange_search_questions` now populates `excerpt`.** Derived from `body_markdown`, which the tool's pinned search filter already returns — `question.excerpt` itself is silently dropped by Stack Exchange from any minted filter ([#17](https://github.com/cyanheads/stackexchange-mcp-server/issues/17)).
- **`stackexchange_list_sites` declares an error contract.** It threw with no `errors[]` before; it now declares `quota_exceeded`, `invalid_parameter`, `invalid_api_key`, and `upstream_unavailable`, and its site-page walk checks quota on every page ([#24](https://github.com/cyanheads/stackexchange-mcp-server/issues/24)).
- **An unrecognized `STACKEXCHANGE_API_KEY` now fails as `invalid_api_key`, a `ConfigurationError`** — Stack Exchange's `bad_parameter` prose naming `key` no longer misreads as a caller input error, and the configured key is never echoed ([#25](https://github.com/cyanheads/stackexchange-mcp-server/issues/25)).
- **A malformed Stack Exchange response body now reports `upstream_unavailable`** on every tool instead of an undeclared classifier error.
