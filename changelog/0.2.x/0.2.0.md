# 0.2.0 — 2026-10-28

## Added

- **`skills/stackexchange-guide`** is a published agent skill, served over MCP as `skill://stackexchange-guide/SKILL.md` through `createApp({ skills })`; it also ships in the npm package, plugin installs, the `.mcpb` bundle, and the Docker image.
- **`stackexchange_search_questions`** reports `appliedSort` on every response, plus `sortOverrideReason` when `minScore` forces the `votes` sort ([#27](https://github.com/cyanheads/stackexchange-mcp-server/issues/27)).
- **`stackexchange_get_thread`** reports `siteConflict` when a URL and a `site` name different sites, saying which one the question was read from ([#34](https://github.com/cyanheads/stackexchange-mcp-server/issues/34)).
- **`throttled` and `pacer_shed`** are declared on all five tools, each with a numeric `retryAfter` ([#30](https://github.com/cyanheads/stackexchange-mcp-server/issues/30)).
- **Root `plugin.json` and `mcp.json`** (Agent Plugins 1.0.0).

## Changed

- **`stackexchange_get_thread`** (breaking: `questionIdOrUrl`) reads a question URL from the site its host names, and `site` is now optional and needed only for a numeric ID. A URL whose host is not a Stack Exchange site, such as `https://stackoverflow-com.translate.goog/questions/N`, is still read from `site` when one is passed, but without `site` now ends `invalid_site`; 0.1.17 read it from Stack Overflow through the `site` default ([#34](https://github.com/cyanheads/stackexchange-mcp-server/issues/34)).
- **`quota_exceeded`** is non-retryable: one upstream request instead of four ([#33](https://github.com/cyanheads/stackexchange-mcp-server/issues/33)).
- **`stackexchange_get_tag_faq`** describes its results as Stack Exchange's own selection in its order, not sorted by score; every `site` input also documents the domain form (`superuser.com`).
- **`.mcpbignore`** is root-anchored and covers the new root dev paths; `lint:packaging` checks it.
- **README** getting-started section trimmed to the hosted and `npx` paths.

## Fixed

- **Throttles** (`throttle_violation` envelope, bare HTTP 429) end in `throttled` with `retryAfter` instead of `-32602` or `-32003`, and later calls are held for the stated wait. A backoff that outlasts the call's 50-second budget fails at once, and a queued call sheds as `pacer_shed`, instead of both running to `retry_deadline_exceeded` ([#30](https://github.com/cyanheads/stackexchange-mcp-server/issues/30)).
- **`temporarily_unavailable` and `internal_error`** envelopes, which Stack Exchange wraps in HTTP 400, end in `upstream_unavailable` and retry like a 5xx instead of surfacing as `-32602` ([#33](https://github.com/cyanheads/stackexchange-mcp-server/issues/33)).
- **`stackexchange_get_thread`** with a question URL from another Stack Exchange site returned an unrelated Stack Overflow thread ([#34](https://github.com/cyanheads/stackexchange-mcp-server/issues/34)).
